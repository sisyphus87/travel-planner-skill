# 小红书体验研究

小红书是**不可降级的主信息源**（个人定制，2026-10）：用于各类信息检索和核查——尤其是容易忽略的**区间交通**（跨城班车/拼车/景区直通车/文旅专线）；**难查到的信息优先问小红书**（多帖互证常比网页搜索更接近当下真实运营状态）。它仍不负责最终确认开放、票务或路线硬事实——那部分以官方为准。

## 适合研究

- 城市分区与游玩节奏；
- 拥挤、排队和建议到达时段；
- 拍照位置、天气体感和穿着建议；
- 近期施工、体验下降或常见踩雷；
- 餐厅氛围、分量和排队体验；
- **区间交通**：线路是否还运营、发车时刻、上车点、避雷（哪趟车不走高速/只到半路）；
- 官方渠道查不到或过期的细节（游客中心寄存价格、退改实操、集合点实况）。

## 不应单独决定

- 是否营业或闭馆；
- 是否需要实名预约；
- 官方票价和退改规则；
- 公交末班、航班或铁路规则；
- 医疗、食品安全等高风险事实。

## 内置 AI（点点）

用户习惯自己用小红书 App 左侧栏「点点 AI」提问做检索合集，再作为输入对接过来：

- Agent 应**主动建议用户先跑点点合集**（尤其大目的地信息收集阶段），可适当替代直接搜索——省 MCP 调用、降风控压力；
- 点点结果是二手聚合，**不替代多帖互证**：关键结论仍要抽原帖核实，评论区也要看；
- 有页面/浏览能力时，可参考点点页面交叉验证。

## 研究方法

1. 以“城市 + 街区/月份/主题 + 本地人”搜目的地信号（按点赞排序、半年内优先）；
2. 店级/线路级研究只针对已经通过位置和营业初筛的候选；
3. 优先近期内容，记录发布日期；
4. 至少比较多个独立内容，区分共识与个例；
5. **评论区必看**：差评、避雷、服务态度、"更优替代"（如"不如斜对面那家"）是重要信号，采集进推荐备注；
6. 用官方/地图来源复核硬事实；
7. 把结论写成软信号，如“多篇近期笔记提到上午排队较短”。

## 广告甄别

- 只采含具体时间/价格/流程的实访细节帖；
- 营销腔信号：通篇夸赞无槽点、"闭眼冲"式话术、评论区空洞（满分/码住）、@美食薯、单推一家；
- 疑似软文**降权**：不作唯一依据，须互证；
- 高赞“无广”标记帖与评论区真实互动是加分项。

## 不可用时（红线）

**中止并提醒用户**，不要用网页搜索摘要、记忆或编造内容继续——小红书在本方法论里不可降级。不要要求用户扫码登录，不要绕过验证码或访问限制；提醒用户恢复 MCP 服务（本机 18060 单例版需 `-headless=false` 启动）或改由用户用点点 AI 自查后提供结果。

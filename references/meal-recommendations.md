# 美食推荐规范（个人定制）

每餐给出"少而准"的推荐，而不是餐厅大全。来源双核：**小红书（MCP 或 browser use）+ 高德评分/人均/距离**，两者缺一不落店。

## 推荐原则

1. **每餐 1-2 个**就够：主推 + 至多一个备选，写清店名、位置、评分、人均、营业时段。
2. **早餐除非"合适且近"否则不推**——最近的落点就是酒店门口步行 100-300 米内、开门时间赶得上出发的那种；否则写"酒店早餐/打包"。
3. **景区附近的餐可以不推荐**（跟团/园内凑合型），一句"景区内解决/自带干粮"即可，不硬凑店名。
4. **就近优先**：除非很有特色且强烈推荐，否则都不要太远——推荐半径锚定"酒店/当日节点步行或打车 5-8 分钟内"；集合点/散团点旁的店是最优解。
5. 已定正餐（用户指定或行程锚定）不换，只补备选。

## 落店流程

1. 小红书搜"城市 + 街区/品类 + 本地人"（按点赞排序，半年内）；
2. 挑 2-3 个高赞帖看详情，**评论区必看**：差评/避雷/更优替代是关键信号；
3. 高德 `maps_text_search` → `maps_search_detail` 核实：评分 ≥4.4、人均、营业时间、精确坐标；
4. 坐标算与酒店/当日节点的距离（或跑 route 实测），超出就近原则的换掉；
5. 写入 `meals`（main/alt：name + 坐标 + why + price，source 用 amap-mcp）+ 时间线 POI note + 当日清单卡片，三处同步。

## 甄别广告信号

- 正文通篇夸赞、无具体槽点、"闭眼冲/香到跺脚"式营销腔；
- 评论区空洞（"满分""码住"）或无人格内容；
- 文末带品牌话题/@美食薯、全文只推一家且信息可复用于任何店。

软文嫌疑帖**降权**：不作唯一依据，须有第二来源互证或高德评分佐证。

## 红线

小红书或高德任一不可用时**中止美食推荐环节并提醒**，不用记忆或网页摘要凑推荐——宁缺毋滥。
